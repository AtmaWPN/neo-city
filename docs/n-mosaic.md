## The Board

- You're given a grid (configurable, e.g. 9×9). Not every cell is playable — a contiguous shape is randomly carved out of the grid, and only cells inside that shape (the included cells) matter. Cells outside the shape are blacked out and empty.
- Each playable cell can be filled with one of N colors (configurable; the palette holds the swatches).

## The Clues

- Some cells display a clue: a number printed in a color. A clue at cell C with value k written in color X means: Exactly k cells in cell C's neighbourhood must be colored X.

- The neighbourhood of a cell is the 3×3 block centred on C, *including* C itself.

- A cell can hold more than one clue (e.g. multiple colored numbers separated by commas, as in the multi-clue rendering code). Each clue is an independent constraint.

## Winning the Puzzle

You win when both conditions hold simultaneously:

1. Every included (playable) cell has been filled — no empty cells remain in the shape.
2. Every clue is satisfied exactly — for each clue, the number of its neighbors currently painted with the clue's color equals the clue's count (guessCount === clue.count).

## Techniques

~Simple Remainder~
- INPUT: Single Clue
- WHEN: Number of remaining empty cells in neighbourhood equals the effective clue value (clue value minus cells in the neighbourhood that already match the clue)
- OUTPUT: Those empty cells are marked with the clue color

~Simple Candidate Generation~
- Remove candidates from empty cells of satisfied clues

~Last Candidate~
- INPUT: Single Cell and all other clues that include that cell in their neighbourhood
- WHEN: The Cell is empty and has only one candidate color (candidates are calculated using satisfied clues to rule out the clue color in all empty cells in that neighbourhood)
- OUTPUT: The cell is marked with the candidate color

~Simple Candidates Remainder~
- INPUT: Single Clue and all other clues with neighbourhoods that overlap with that clue's neighbourhood
- WHEN: Number of cells with the clue color as a candidate in clue neighbourhood equals the effective clue value
- OUTPUT: Those cells are marked with the clue color

Simple Subset Remainder
- INPUT: Single Clue and all other same color clues with neighbourhoods that are contained by that clue's neighbourhood
- WHEN: The neighbourhood of this clue (A) fully contains the neighbourhood of another clue (B) and effective value of A minus the effective value of B is equal to the number of empty cells in A's neighbourhood but not B's
- OUTPUT: Those empty cells are marked with the clue color

Simple Subset Remainder for differently colored clues
- INPUT: Single Clue and all other differently colored clues with neighbourhoods that are contained by that clue's neighbourhood
- WHEN: The neighbourhood of this clue (A) fully contains the neighbourhood of another clue (B) and effective value of A minus the effective neighbourhood of B plus the effective value of B is equal to the number of empty cells in A's neighbourhood but not B's
- OUTPUT: Those empty cells are marked with the clue color

Effective Clue N-TNS
- INPUT: N Clues (C1,...,Cn) with different colors with overlapping neighbourhoods
- WHEN: The Sum of the Effective Clue values === number of empty cells in the neighbourhoods
- OUTPUT: Cells in Ci but not any of the other Clues => Color of Ci for all i in [1,n]

TNS Chaining - For any set of clues, if no same-color Clues share an empty cell, the sum of the Effective Clue values equals the number of empty cells in those Clues' neighbourhoods and the TNS condition holds.

Excluded Difference - Like TNS but we can treat clues as inverted (i.e. X cells in Y region are NOT color Z), "NOT color Z" is considered to be a color that counts as the same color of all colors except color Z for the purposes of TNS-chaining

### Implied Clues
- Implied Clues are like real Clues except you can't see them and they govern smaller areas
- Just like a real Clue an Implied Clue says X of these Y cells are Z color, but the Y cells are not a cell neighbourhood
- Implied Clues can be used in all the same ways as real Clues as well as some new ones due to their varied size.

Implied Clue Creation
- Implied Clues are generated by combining other Clues
- Effective Clues are a special case of Implied Clues where the Clue is generated by a single Real Clue

Simple Implied Clue Generation
- Only create Implied Clues from the combination of two Effective Clues
- Either Via Subset Remainder or TNS
- There's also theoretically a type of Effective clue that takes into acount candidate restrictions

Implied Clue Resolution Cases
- Simple Remainder - Implied Clue number equals Implied Clue size
- Non-intersecting - Useless without additional information
- Identical Areas - Restricts candidates if the Implied Clue values sum to the total area 
- Contained (Subset A is a subset of Subset B) - Extersection => Subset C, either Subset C is a simple remainder or a propagated subset
- Overlapping - This can be either TNS or ED depending on whether the Implied Clues are the same color or different
  - Overlapping Clues can also be resolved via count based logic with a large clue containing both
- The Contained and Overlapping cases can occur simultaneously with several Implied Clues creating very complex logical structures (e.g. One large Implied Clue can consume multiple non-overlapping contained Implied Clues to create a new Implied Clue for the remainder)

## Advanced Techniques (AI-Generated and mostly useless)
Notation: N(C) = the 3×3 block centred on C, **including C itself** — the clue cell counts toward its own clue (9 cells in the interior, 6 on an edge, 4 in a corner; fewer still beside blacked-out excluded cells). All counts are over included cells only. Each included cell takes exactly one of the N colours, so for every cell C the N colour-counts across N(C) always sum to |N(C)|. K(R) = the number of k-coloured cells in region R.

Because C ∈ N(C), a clue (C, k, v) is an assertion about the whole block: exactly v cells of the block are coloured k. If C's own colour is already decided, the requirement on the other 8 cells adjusts accordingly — v − 1 if C is k, v if C is not k. Effective values are always computed after stripping already-matched cells and applying this centre adjustment.

### Symbols & Terminology

- **N(C)** — the neighbourhood of cell C: the 3×3 block centred on C, including C itself.
- **|R|** — the **size** (cardinality) of a region R: how many included cells it contains. E.g. |N(C)| = 9 in the interior, 6 on an edge, 4 in a corner; |A∖B| is the number of cells exclusive to A.
- **R ∖ S** (also written **R \ S**) — **set difference / minus**, read “R minus S” or “R without S”: every cell that is in R **and not** in S. A∖B is A's *exclusive region* — the cells only the A clue can see.
- **R ∩ S** — **intersection**, read “R and S” / “R intersect S”: every cell that is in **both** R and S. A∩B is the region shared by the two clues' neighbourhoods.
- **R ∪ S** — **union**, read “R or S” / “R union S”: every cell that is in R, S, **or both**. ∪ N(Ci) (read “the union over i of N(Ci)”) is every cell lying in at least one of the selected clues' neighbourhoods.
- **∈** — “is in / belongs to”: C ∈ N(C) means C is a member of its own neighbourhood (true under the official rules).
- **K(R)** — the **count of k-coloured cells** in region R, where k is the clue colour being reasoned about. Only included cells coloured exactly k count — other colours and empty cells do not. So K(A∖B) reads “the number of k-coloured cells that lie in A but not in B”.
- **vA, vB, vi** — the **value** (printed number) of clue A, clue B, or clue i. v is counted over the whole neighbourhood including the clue cell itself.
- **Σ vi** — **summation**: the total of the clue values of the selected clues (e.g. vA + vB + vC).
- **(C, k, v)** — a clue written as a **tuple**: at cell C, exactly v cells of N(C) are coloured k.
- **{ci}** — **set of colours**: the distinct colours used by the selected clues (duplicates dropped).
- **k / c / d / cA / cB** — variable names for specific colours; k is usually the clue colour in play, while c and d are two different colours being compared.
- **exclusive region / A-only cells** — cells that lie in one neighbourhood but in no other neighbourhood under consideration (the A∖B region), as opposed to cells in the overlap A∩B.
- **candidate** — a colour a still-empty cell could legally take without breaking any clue; Last Candidate and APE reason over each cell's candidate set.
- **effective value** — the clue's target after subtracting cells already fixed to the clue colour and cells that can never take it (see centre adjustment above).

Neighbourhood Conservation (Colour Sum Identity)
- INPUT: A cell C and its clues (one per colour, real or implied)
- WHEN: Every cell of N(C) — including C itself — has exactly one colour, so the colour counts over N(C) always sum to |N(C)|. If N−1 of those counts are pinned down, the last one is forced. For N = 2, the clue (C, k, v) is entirely equivalent to its complement clue (C, other colour, |N(C)| − v). Decide C's own colour first: it changes the target for the remaining 8 cells by exactly one.
- OUTPUT: The missing count — Simple Remainder / Simple Remainder Candidates then conclude the actual cells. Also run every other technique against the complement clue as well as the original.

Difference Identity (Symmetric-Difference Division)
- INPUT: Two clues A, B of the same colour k
- WHEN: Always. vA = K(A∖B) + K(A∩B) and vB = K(B∖A) + K(A∩B), so vA − vB = K(A∖B) − K(B∖A) exactly.
- OUTPUT: An exact equation over the two exclusive regions. This is the engine behind Boundary Lock, Line Shifts, and the cycle arguments below.

Boundary Lock
- INPUT: Two same-colour clues A, B
- WHEN: vA − vB = |A∖B|
- OUTPUT: Every A-only cell is colour k and no B-only cell is colour k (drop k from all B-only candidates)
- Also: vA − vB = −|B∖A| flips it (all B-only cells are k, none of A-only). If vA = vB, both exclusive regions hold the same number of k-cells — with capacity or candidate facts on either side this usually forces both regions uniformly. (ED is the mixed-colour cousin; Boundary Lock is the same-colour extreme case and marks cells directly.)

Line Shifts (Translational Difference)
- INPUT: Two same-colour clues whose centres are exactly one step apart
- WHEN: Always — the Difference Identity projected onto the 3×3 grid. Because N(C) includes the centre, each clue cell lies inside the other clue's neighbourhood (A ∈ N(B) and B ∈ N(A)), so the two centres cancel out of the exclusive regions entirely. For A at (r,c) and B at (r+1,c):
    N(A) = rows r−1..r+1, cols c−1..c+1 and N(B) = rows r..r+2, cols c−1..c+1
    so A∖B = row r−1 (3 cells), B∖A = row r+2 (3 cells), and
      vA − vB = K(row r−1, cols c−1..c+1) − K(row r+2, cols c−1..c+1)
  The clue values vA and vB already include the centres' own colours, so no correction terms are needed.
- OUTPUT: An exact relation between two 3-cell row bands. One band is always the leftover opposite the overlap, so resolving one band (Simple Remainder, Last Candidate) resolves the other. Columns work identically; diagonal steps (A at (r,c), B at (r+1,c+1)) have L-shaped exclusive regions of 5 cells each.

Chaining: a whole column (or row) of same-colour clues gives one such equation per adjacent pair — a small linear system over the bands. Solving the chain jointly pins bands arbitrarily far from the clues, and closed loops provide global consistency checks.

Closed-Loop Consistency & Deadly Cycles
- INPUT: A closed loop of Line-Shift equations
- WHEN: A loop that returns to its start with a non-zero accumulated difference means the clues contradict (broken puzzle). A loop that closes with zero difference and has no cell pinned from outside allows a consistent global flip of its cells (k ↔ other colours) whenever each equation's two exclusive regions have equal size — as they always do for pure orthogonal loops — giving two interchangeable colourings.
- OUTPUT: In uniquely-solvable puzzles (SAT generation) a fully free loop cannot exist — at least one of its cells must be forced by outside information, so hunt there (candidates, other clues, Forcing Chains). In random puzzles, treat a free loop as proof the puzzle is under-constrained. Uniqueness reasoning never applies to randomly generated boards.

Cover Lock (Generalised Total Neighbourhood Sum)
- INPUT: Any set of clues C1..Cm with colours c1..cm; U = ∪ N(Ci)
- WHEN: The clue values sum to the union size, Σ vi = |U| (reachable once candidate rules stop cells from wasting counts on the wrong exclusive regions)
- OUTPUT: Every cell of U is coloured by exactly one of the colours ci among the clues whose neighbourhood contains it. Cells in U with a single surviving candidate in {ci} are marked; cells with no surviving candidate in {ci} are contradictions. For m = 2 with different colours this collapses exactly onto TNS; for m ≥ 3 it produces constraints no pair of clues can see on its own.

Union Counting (Min–Max Through the Intersection)
- INPUT: Two same-colour clues A, B; m = the number of intersection cells still able to take colour k
- WHEN: K(U) = vA + vB − K(I) always lies in [vA + vB − m, vA + vB]; this is useful when that interval slices the number of cells of U that are already decided
- OUTPUT: A forced lower/upper bound on the k-cells among the remaining empties of U; combined with candidate pools this marks individual cells and prunes candidates on both sides.

Aligned Pair Exclusion (APE)
- INPUT: Two empty cells X, Y with 2+ candidate colours each, and all clues whose neighbourhoods contain both
- WHEN: For a candidate pair (a for X, b for Y), assigning both at once already breaks some shared clue — its count exceeds v, or its unfulfilled remaining need exceeds the remaining empty cells
- OUTPUT: Strike that pair; if a candidate of X survives in no pair, delete it from X (symmetrically for Y). The most complete pair-level reasoning available short of full SAT search.
